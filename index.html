01 / 一分钟看懂

你只需要记住三件事

图鉴不是「skill 商店」，是一个决策工具。它帮你把「227 选 1」压缩成「2 选 1，再 3 选 1」。

STEP 1

先定路线

问一句：对方要不要用 PowerPoint 打开并编辑？要 → PPTX 路线（79 个）；不要 → HTML 路线（83 个）。这一步砍掉 2/3 候选。

STEP 2

再看脸

去「风格图库」翻 534 张样图。看着对的那几张，点开就是对应的 skill。不用先理解 skill 是什么。

STEP 3

复制就走

详情抽屉里复制安装命令，图库里点风格 ID 复制提示词，粘给你的 Agent，剩下的它自己走完。

一句话先问「能不能编辑」，再问「好不好看」。顺序反了，就会挑到一个好看但交不出去的方案。

03 / 五个动作

从打开网页到拿到成品

按顺序走一遍，中间不需要思考「skill 是什么」。

1

回答那个唯一重要的问题

首页往下滚，第一块就是它：有人需要用 PowerPoint 打开你的交付物并编辑它吗？

  • 要 → PPTX 路线。交付物是 .pptx，对方能改字、改图、改页序。适合经营月报、投标、交给非技术同事二次编辑。
  • 不要 → HTML 路线。交付物是一个 .html，浏览器打开即放。设计天花板高得多，适合分享、演讲、发布会、群里看。
坑最贵的错误不是选错 skill，是选错路线。花三天做了一个极漂亮的 HTML deck，结果对方要拿去改第 12 页 —— 全部作废。
2

用筛子把 227 收到个位数

进「全部技能」，按四层收窄。每一层点一下就好，右侧数字会实时变。

筛什么怎么用典型场景
路线点「网页 HTML」或「原生 PPTX」已经在第 1 步定了，必选
层级S = 5k+ star 规模验证；A = 100–5k 实用候选；B = 新/小众怕踩坑就只留 S + A
许可MIT / Apache 可商用；Copyleft 先看协议要放进对外产品时必查
能力点亮「→ PPTX」「数据图表」「演讲者模式」等有硬性要求时才点，点多了会筛空
技巧先只点「路线」，记住剩余数量（比如 83）。再加一个你真正在意的能力，看它掉到多少 —— 掉得越狠，说明这个能力越稀缺。
3

点开卡片，读那张体检卡

抽屉里从上到下是：一句话定位 → 标签（路线 / Tier / 许可 / 核读 / star / 综合分 / 更新时间）→ 适合什么 → 风格 ID → 亮点 → 原文证据 → 能力矩阵 → 安装命令 → 样图。

只看三处就够决策：

  1. 适合（bestFor）：作者自己写的适用场景，比 tagline 准。
  2. 能力矩阵：你要的能力是「支持」还是「未提及」。
  3. 原文证据：带「人工核读」标记的条目，会贴出 SKILL.md 里的原句，可以直接判断真假。
口径能力矩阵里的「未提及」不等于不支持，只代表项目文档没写。要用于正式交付，必须自己实测一次。
4

复制两样东西

安装命令在抽屉里，点「复制」。提示词在风格图库里，点风格 ID 那个等宽标签 —— 复制到的是一整句，不是只有 ID 三个字。

用 soft-editorial 这个模板，把【素材】做成一份【页数】页的 deck，
面向【受众】，每页字少一点。

上面这版比图鉴原句多了半句「先给我 3 个预览」，建议直接用：前半句写死了风格 ID，Agent 不用猜；后半句写死了先出预览，你能在半成品阶段叫停。

5

粘给 Agent，然后验收

粘进 WorkBuddy 或任何你顺手的智能体。它会先查有没有装这个 skill，没装会问你要不要装，然后按风格出预览。

验收看三条，缺一条就打回：

  1. 能不能打开。PPTX 用 PowerPoint 打开不报修复；HTML 双击能放。
  2. 能不能改。要编辑的话，文字得是真文本，不是整页截图。
  3. 数字对不对。图表和正文的数字必须来自同一份源，别一处一个口径。
结论图鉴负责「选」，不负责「保证」。选完之后的验收，仍然是你自己的活。
04 / 数据怎么读

页面上每个数字，都能追到出处

图鉴的底层是一份公开登记册。下面两张图就是页面数据的两条主线：路线分布决定你的第一步，能力覆盖决定你的第二步。

路线决定一半的选择题

227 个 skill 按输出路线分布 · 数据源 many-ppt-skills（2026-09-04 刷新）

怎么用：网页 HTML 83 个、原生 PPTX 79 个，两条主线合计 162 个，占全部 227 的 71%。所以第一步永远是问「对方要不要用 PowerPoint 改」，答完这一步，三分之二的候选直接出局。

真正支持 → PPTX 的只有 17 个

能力矩阵命中数 · 读自各项目文档，未提及不计

怎么用：文档明确写了支持「→ PPTX」的只有 17 个，支持「演讲者模式」的只有 4 个，能套企业模板的 7 个。风格好看和能力齐全是两回事 —— 挑完风格，务必把能力矩阵看一眼。

字段字典

字段含义怎么用
路线产出物的形态：html / pptx / hybrid / framework / image / templates / suite第一道筛子，必选
TierS = 5k+ star；A = 100–5k；B = 新/小众怕踩坑只留 S + A
许可MIT / Apache = 宽松；Copyleft（如 AGPL）= 有传染性；未标注 = 商用前必须核对对外产品务必看
综合分star 45 + 活跃 15 + 许可 15 + 人工核读 10 + 能力 15 = 100不是实测质量分，只用于排序，别当评级

注意综合分是按公开数据算的排序依据，不是横评成绩。star 高只说明关注的人多，不说明适合你的场景。

三步用上某个风格

  1. 找：在顶部搜索框输入风格 ID 片段（如 editorial），或直接翻。图库支持按风格 ID 过滤。
  2. 抄：点那张图下面的等宽标签。复制到的是「用 {风格ID} 这个模板，把【素材】做成一份【页数】页的 deck，面向【受众】，每页字少一点。」，三个方括号留给你的内容。
  3. 换：把【素材】【页数】【受众】三处方括号替换成你的内容，其余别动。
提示同一张样图只代表该风格的一页，别指望整套都长这样。要判断整套水平，去抽屉里看这个 skill 的全部样图（最多 6 张）。

07 / 常见问题

六个被问过最多的问题

「安装命令复制了，但我的电脑上没有这个 skill，怎么办？」

把命令和提示词一起粘给 Agent，让它自己装。skill 的本质是一个带 SKILL.md 的目录：用户级放 ~/.workbuddy/skills/，项目级放 {项目}/.workbuddy/skills/。认目录，不认命令。

「综合分 95 的一定比 82 的好用吗？」

不一定。综合分只按 star、活跃度、许可、是否人工核读、能力覆盖加权，反映的是「这个项目被验证的程度」，不是「适不适合你这次的场合」。同一个 95 分的 PPTX 工具，做发布会网页就是错的。

「为什么能力矩阵里全是『未提及』？」

因为很多项目的文档只写了怎么用，没写支持哪些能力。「未提及」是文档缺口，不是能力缺口。要确认，只有一条路：装上去实测一页。

「HTML 路线做出来的东西，对方打不开怎么办？」

HTML 是单文件，浏览器双击就能放，不需要装任何东西。真正的风险是对方要改——HTML 不适合非技术同事二次编辑。这也是第 1 步必须先问路线的原因。

「Copyleft 许可到底能不能用？」

内部汇报、自用交付，基本没问题。要嵌进对外售卖的产品或 SaaS，AGPL 会要求你开源衍生部分，风险很大。拿不准时看仓库里的 LICENSE 原文，别只看图鉴摘要。

「页面上的数据多久更新一次？」

上游登记册刷新后，由同步脚本拉取并重建，页脚会写明「数据同步于」的日期。当前为 2026-09-04 刷新版。

08 / 维护与更新

上游更新了，怎么同步

图鉴的数据来自公开登记册，不是手工维护的表格。上游刷新后，跑一条命令重建即可。

cd F:/work/_ppt-atlas-build
python sync.py            # 拉上游 → 比对新增/移除/有更新 → 补下载样图 → 重建数据
python sync.py --build    # 断网时，仅用本地缓存重建

脚本会打印本次变化：新增了哪些 id、移除了哪些、哪些条目有更新。先审一遍再发布，避免上游误删把页面筛空。
